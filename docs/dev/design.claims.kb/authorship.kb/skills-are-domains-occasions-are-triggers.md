# Skills Are Domains; Occasions Are Triggers

A skill is a domain of law; an occasion is a trigger in the domain
that owns it; the loadable grain is the procedure file the trigger
names. A new occasion is therefore a new trigger entry, not a new
skill -- the skill boundary moves only when a new domain does.

History fused the two: while the skill was the only unit of
occasioned loading, each occasion calcified into a skill of its own
(the notation/file-form split, the three lens skills). Load cost is
priced at the trigger-gated file, so this claim and PARSIMONY pull
together: fewer, coarser skills, with `skill.kb/must-read.kb/` banks
doing the fine routing -- the mechanism that runs today, generalized
by `Skill(llm-triggers)` in design.
