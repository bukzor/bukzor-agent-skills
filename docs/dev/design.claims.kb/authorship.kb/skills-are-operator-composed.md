# Skills are operator-composed

A skill is one transformation; the operator chooses the next one. No
skill invokes a peer, names one as its verifier, or scripts the step
after its own output: the judgment between calls -- which
transformation, on what, whether at all -- is the operator's seat,
and a skill that orchestrates it has taken a decision it was never
delegated. The line to hold: naming the convention an *output* must
conform to (a filing format, a schema) is a substrate dependency and
is fine; naming a peer *transformation* to run is composition, and
composition is not the skill's to do.
