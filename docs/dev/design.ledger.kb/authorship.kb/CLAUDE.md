# authorship.kb -- maintenance guide

How skills in this repo are written: their audiences, names, coupling,
and citation discipline. The claims price everything against the
asymmetry that a skill is written once and paid for on every load.

- `prior:` none -- root theory
- `ontology:` skill, SKILL.md, description, name, author, invoker,
  operator, instance, exemplar, peer, substrate, load, retrieval,
  trigger, composition, token, blind
- `defeated by:` a skill format with per-audience channels (an
  author-facing file beside the invoker-facing body), or a harness
  whose retrieval consults neither names nor descriptions -- either
  dissolves the single-surface economics these claims price.

## What belongs here

A commitment about how any skill here is authored -- a rule whose
reversal would change skill text across the fleet.

## What does NOT belong here

One skill's own design commitments -> that skill's own
`design.ledger.kb/` (precedent:
`../../../llm-claim-ledger/design.ledger.kb/`). The historical record
of a ruling -> `../../adr/`; the ADR holds the act, this collection
holds the standing.
