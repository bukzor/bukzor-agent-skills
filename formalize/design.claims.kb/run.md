# run -- how a run proceeds, and what it spends

A run surveys before it frames, conjectures more than it keeps, and then
does three things to the survivors: hunts their inconsistencies, drives
them toward minimal, and elaborates them far enough to extract from.
What comes out is sorted against the questions the work was bought to
settle.

Spend is part of the design. A run trades thoroughness against tokens
deliberately, and delegation is the lever.

`SKILL.md` is downstream of this theory alone: a change here is a change
to the manual.
