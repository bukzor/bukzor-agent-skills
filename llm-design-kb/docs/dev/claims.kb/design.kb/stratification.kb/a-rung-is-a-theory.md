# A Rung Is a Theory

Each rung is a theory in the `Skill(llm-claims)` sense -- a defining
claim beside its collection -- and not a new kind of object.

The question this answers is whether some more "graph-native" layout
would serve better. There is none to prefer: in a ledger a theory
*already is* a graph node, rendered by the same tools as every other
claim, and the container view and the graph view are two readings of
one dataset. Choosing a non-theory representation would cost
confinement, which is the one thing rungs do that tags cannot -- a
claim under `requirements` that coins architecture words gets
reported.

The declined alternative is fully emergent stratification: let a
claim's rung be its depth in the motivation DAG. It fails because
depth is topology and a rung is a speech act. Two claims equidistant
from mission can be a requirement and a deliverable.
