# Each Rung Says Only What Its Question Asks

A claim answers its rung's question and leaves everything below it
underdefined. A mission says what problem and for whom, not what solving it
consists of; a goal states a stance, not the features that realize it; a
requirement states what must be true, not the format that makes it so.

Walk each claim against its rung's question (the record's own `design.md`
names the rungs; `SKILL.md`'s table is the default set). For each sentence,
ask: could it change without the rung's question getting a different answer?
Then it answers a lower rung's question, and is a finding.

Repair: find where the detail lives below. If it is there, cut it here; if
nowhere, move it there rather than delete it ([ONE_HOME]).

`state-properties-not-mechanisms.md` is this pass's requirement-and-architecture
case. Receipt: my-own-shadertoy (`github.com/bukzor-sandbox/my-own-shadertoy`),
session 59b55f01 -- a mission that defined understanding, and five goals
carrying architecture's vocabulary and the milestone ladder's feature list.
