# principles.kb -- design authorship

Reusable rules for *writing* a design record well, distilled from
practice across projects. Distinct from any one project's own
`goals`/`requirements` rungs: those state what a specific system must
do; these state how any design record should be authored.

## What Belongs Here

- A rule about authoring design claims that generalizes beyond any one
  project's record
- One principle per file, kebab-case, descriptive of the rule itself

## What Does NOT Belong Here

- Project-specific mission/goals/requirements -- those live in that
  project's own ledger
- Historical narrative of how a principle was discovered -- an ADR or
  devlog's job, not this collection's

## When to Add

When a design-authoring lesson recurs across two or more projects, or
is general enough to state once for all future ones. Adding one means
adding its occasion to
`../must-read.kb/when/deciding-what-a-design-claim-should-say.md`,
which is how anyone finds it.
