# design.claims.kb/ -- llm-kb's design commitments

## What belongs

A claim about how the kb pattern works or should work: schema binding,
what a roll-up carries, what the walk counts as corpus, what the
validator enforces, what runs on a schedule to catch drift.

One claim per file, `kebab-case.md`, named in prose. `label:` +
`standing:` required; `why:` where a real warrant exists.

## What does NOT belong

- A transformation with a scope and a status -> `../../migrations.kb/`
- A task with an owner and a deadline -> `../../.claude/todo.kb/`
- The settled pattern, stated for a user -> `../../SKILL.md`
- A commitment binding a different skill -> that skill's own ledger

## Standing, in this ledger

`open` is a question nobody has ruled. `agent` is my call with the veto
window open -- edit the file to veto. `user` is yours. `bare` needs no
judge: it is checkable, and `verify:` says how.
